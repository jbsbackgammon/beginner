# 初級戦管理（beginner）

GitHub Pages上で動作する、バックギャモン大会の成績管理ツールです。3画面（選手管理／進行管理／成績管理）を備えています。

## GitHub Actionsで公開する（初回のみ設定）

1. GitHubで公開リポジトリ `jbsbackgammon/beginner` を作成し、このZIPの中身をリポジトリのルートにアップロードしてください（ZIP自体ではなく中のファイル）。`.github/workflows/pages.yml` も配置します。
2. GitHubの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。従来の `Deploy from a branch` 設定とは異なります。
3. `main` にファイルを追加・更新すると、Actionsの「GitHub Pages 公開」が自動起動し、ビルド後に公開されます（手動実行も可能）。
4. 公開URL：`https://jbsbackgammon.github.io/beginner/`

GitHub Actionsは **ubuntu-24.04** 固定、Node.js 24対応世代の `checkout@v6` / `configure-pages@v6` / `upload-pages-artifact@v5` / `deploy-pages@v5` を使用します。npm・ビルド依存パッケージは不要です。Actions中の公開前テストジョブは設けず、アップロード→ビルド→公開のみを行います。

## キャッシュ対策

- Actionsの `build_pages.py` が `style.css`、`src/app.js`、`src/ranking.mjs` に内容のハッシュを含む別名を付けてデプロイします。変更のないファイルは同じ名前、変更されたファイルは新しい名前になるため、古いJS/CSSが継続使用される問題を軽減します。
- 最新公開版を記録する `build-info.json` も自動生成。既にページを開いている場合は5分ごと／再表示時に更新を確認し、新版があれば「最新版に更新」を表示します。**入力中の画面が勝手に再読み込みされることはありません。**
- 更新ボタンはURLに版番号を付けて再読み込みすることで、古いHTMLが残る可能性を減らします。
- GitHub PagesのHTTPキャッシュヘッダーやCDNキャッシュを任意に設定できるわけではないため、**更新直後に100%即時反映される保証ではありません**。反映のタイミングにはGitHub側の配信状態も関係します。
- これらはプログラムファイルのキャッシュ対策です。**試合記録のブラウザ内保存（localStorage）は削除しません**。キャッシュクリア時にサイトデータまで削除すると記録を失う可能性があります。

開発時のビルド：`python3 build_pages.py --output _site`。ローカルの `index.html` を直接開く代わりにHTTPサーバーでプレビューしてください（例：`python3 -m http.server 8000 --directory _site`）。

ヘッダー左にページ切替、右に種目選択を表示し、初期選択はDay1です。「選手管理」は大会選択欄なし、「進行管理」は総合を除く6大会から選択します。「JSON出力」「JSON取込」「テスト」「全削除」はヘッダー右端に配置しています。

### v36 テストデータ生成（現行仕様）

- ヘッダーの「テスト」をクリックして確認すると、**選手30名と各大会300件、全6大会合計1,800件**の試合結果をランダム生成します。初級戦総合はDay別の成績から自動計算し、独立した試合結果は生成しません。
- 選手名・よみはランダムな日本語の姓名と対応する読みを使用し、同姓同名を作りません。
- 30名全員を各大会の出場者として設定し、各大会の435通りの異なる組み合わせから300組を抽選します。同一選手同士、出場未登録、同一大会内の重複対戦は生成しません。得点は種目別のルールに合わせます。
- 各大会には対戦待ちの選手もサンプル登録します。30名の選手、6大会の成績、初級戦総合、対戦斡旋、PDF出力を確認できます。
- **実際の大会データは上書きしません。** テスト専用データへ切り替え、「テスト終了」で元の大会データに戻ります。テスト中の変更は終了時に破棄されます。テスト終了後に再実行すると新しいランダムデータを生成します。
- 履歴画面は既存の仕様どおり種目ごとに直近80試合を表示します。300件すべての結果は保存・集計され、検索で過去の試合を抽出できます。

## 画面・レギュレーション

- **進行管理**：左上「結果入力」、左下「対戦斡旋」、右「結果履歴」。選手番号・選手名プルダウンからの入力に対応。「対戦待ち／未対戦相手」の2列に、対戦済み選手と未対戦相手の番号を表示。番号ボタンにカーソルを合わせると相手氏名が表示され、クリックで確認ダイアログを開きます。OKの場合はその両選手を対戦中として斡旋候補から除外し、結果入力欄に2名を選択します。対戦中エリアは表示せず、斡旋済みの選手は対戦待ち候補から除外します。結果登録後は対戦中から自動解除されます。対戦中の割当は同じブラウザ内に保存され、JSONバックアップにも含まれます。対戦済み組み合わせは重複警告（登録自体は可能）。左右の選手は横並びにし、番号・名前の見出しを省略して、それぞれの入力幅いっぱいに勝敗ボタンを表示。入力欄の「削除」ボタンは設けません。右側勝者チェックボックスは廃止し、勝敗はボタンで選択。得点プルダウンと「結果登録」ボタンを横並びにし、登録ボタンの幅は従来の半分。得点の項目名は表示しません。結果入力・結果履歴のエリア幅はPCで1:1（小画面では縦並び）。結果履歴は「選手名／結果／選手名／操作」の4列で、両選手名の列は同幅。選手番号と氏名を「#1 あ」の形式で表示し、勝者を左（引き分けは番号順）に配置。勝者の得点は赤、引き分けは両得点を緑で表示。操作の見出しは左揃え。対戦斡旋には検索欄・未対戦組数の表示を設けません。結果入力の左右選手間には「VS」を表示します。結果履歴の直近件数・全件数の表示を省略します。
- **選手管理**：番号別の一覧表で「選手」「よみ」を直接入力。6大会の出場を同じ大きさの「出場」（薄黄色）／「ー」（白地・グレー文字）ボタンで管理。名前未入力行は大会操作を無効化。初期の番号欄は1～30番で、最下行「次の10行を追加」を押すと10行ずつ追加します。既存の31番以上の選手は隠さず、表示行数はブラウザとJSONへ保存します。
- **成績管理**：大会名・開催日・PDF出力と、その大会の順位表を表示します。選手番号と名前は「#9 け」形式で1列表示し、順位判定に使う項目名に①②③を付けます。開催日の変更時、保存通知は表示しません。
- **画面のスクロール**：全ページで縦スクロールはページ全体に統一し、ヘッダーはスクロール中も上部に固定。狭い画面では表をカード状に折り返し、横スクロールを発生させません。

| 区分 | 順位決定（優先順） | 結果入力 |
| --- | --- | --- |
| 初級戦 Day1/2/3 | 得失点差、勝越、勝率 | シングル1点、ギャモン2点、バックギャモン3点 |
| 小学生選手権 | 得失点差、勝越、勝率 | 初級戦と同じ1・2・3点（単独大会・総合なし） |
| キューブ有RR | 得失点差、勝越、勝率 | 1,2,3,4,6,8,12点（4倍キューブまで） |
| 2pt RR | 勝越、勝率、試合数 | 2-0、2-1、1-1、1-2、0-2 |
| 初級戦総合 | 得失点差、勝越、勝率 | Day3含む2日以上の成績。得失点差が上位の2日採用 |

同順位は同順位（競技順位方式）。2ptの勝率は勝／（勝＋負）で、引き分けは除外します。

初級戦総合の採用2日で得失点差が同じ場合は、従来Excelの扱いに合わせて勝越、試合数、早いDayの順に優先します。

## データ保存に関する注意

GitHub Pagesは静的サイトです。試合結果は利用中のブラウザ内（`localStorage`）だけに保存され、**他の端末と同期されません**。ブラウザデータを消すと失われるため、ヘッダーの「JSON出力」から定期的にバックアップを保存してください。アプリの更新では `localStorage` の保存キーを変更しません。

選手名簿や過去の試合記録を含むJSONは配布ZIPに含めていません。個別提供したJSONを必要に応じてヘッダーの「JSON取込」から取り込んでください。公開リポジトリに個人情報・試合のJSONを直接置かないでください。

## ソース

- `index.html` / `style.css`：ページ本体とスタイル
- `src/app.js` / `src/ranking.mjs`：画面操作・順位計算
- `build_pages.py`：公開専用のハッシュ付与＋更新通知挿入処理
- `.github/workflows/pages.yml`：GitHub Pages自動公開
- `tests/ranking.test.mjs`：ローカル用集計テスト（`node --test tests/ranking.test.mjs`）

生成される `_site/` はアップロード不要です（Actionsが毎回生成します）。

### v29-v30 入力制御・通知

- 結果入力の左右選手プルダウンは選手番号の昇順（v29の仕様を維持）。
- 2人の異なる登録済み選手が揃うまでは「勝」「負」（2ptの「引分」を含む）を非活性にし、得点も選択できません。
- 勝敗（または引分）が明示的に選択されてから得点プルダウンが有効になります。選手を変更した場合は勝敗・得点を解除します。
- 結果登録ボタンは上記の必須項目が揃い、得点が選択・整合した場合のみ有効になります。
- 「対戦を組みました。」「試合結果を保存しました。」などの処理通知は、ヘッダー内で黄色背景・濃色文字・枠線を使って強調します。表示位置と約4秒後の自動消去は変更しません。

### v31 結果入力の選手選択候補

- 結果入力で左選手を指定すると、その選手は右選手の氏名プルダウンに表示されず、右選手を指定した場合も左選手の候補から除外されます。
- 選手番号を直接入力した場合にも候補を即時更新します。選択を取り消す、または別の選手に変更すると、除外していた選手を候補に戻します。
- 選手番号順の並び、同一選手の結果登録禁止、勝敗・得点の入力制御は引き続き適用します。


### v32 6時間経過時の大会名確認

- 「進行管理」で新しい試合結果を登録するとき、全大会データを通じて前回の成功した結果登録から6時間以上経過していた場合は、大会名と対象種目を表示する確認ポップアップを出します。
- 「OK」で登録を続行、「キャンセル」で登録せず入力内容を維持します。6時間未満、または初回登録時は表示しません。
- 結果の修正は新しい試合登録とはみなさず、この確認や経過時間の更新の対象外です。
- 登録日時は大会データ内に保存され、JSON出力・取込でも維持されます。v31以前の結果は、生成時刻が含まれる試合IDを使って最新登録時刻を判定できます。
